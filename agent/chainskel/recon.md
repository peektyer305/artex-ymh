# chains-recon L3 意思決定チェーン(場面→判定基準→方向転換;chains コーパスから蒸留,完全な Q&A は skills/chains-recon/refs/ を参照)
- 場面:ルートドメイン/社名しかない|判定基準:まず面を広げてから打点する。権限境界の確定→組織の関連付け→アセットの収束。複数ソースで帰属を交差検証し、新規アセットがゼロに近づき新主体が無ければ収束|方向転換:名称からの逆引きでノイズが大きければフィンガープリントのアンカーに替える(既知 IP/favicon hash/証明書 SAN をシードに)
- 場面:サブドメインを列挙|判定基準:常にパッシブ優先(CT/パッシブ DNS/空間測量/検索、ゼロアラート)。能動的ブルートフォースは既知の命名規則に合わせた辞書で盲点を補う|方向転換:DNS がレート制限されたら複数リゾルバのローテーションで並行度を下げる。または ASN/証明書 SAN/favicon の逆引きへ
- 場面:サブドメインのブルートフォースでワイルドカード DNS が疑われる|判定基準:ランダムな超長の存在しないサブドメインも解決に成功 = ワイルドカード DNS。ブラックホール IP 集合でフィルタし、本物のサブドメインは HTTP レスポンス/証明書 SAN を重ねて二次判定|方向転換:内容も汎化されるなら CT/パッシブ DNS 履歴に頼る。区別できないなら ROI が低いとみなし、撤退して IP セグメント直接スキャン/favicon 関連付けへ
- 場面:サイト全体が CDN 配下|判定基準:複数経路でオリジンを探す(履歴 DNS/CDN 未接続のメール用テストサブドメイン/同一証明書・同一 favicon の逆引き)。Host 衝突で一致する業務内容が返ればオリジン確定|方向転換:複数経路で出なければ貫通を諦めてアプリケーションレイヤーへ。または CDN に載っていない姉妹アセットを打つ。オリジンは目的ではない
- 場面:ポートスキャンと BAN|判定基準:まず top ポートで面を取り、高価値ホストはさらに全ポート。セグメント全体が同時に無応答 = ファイアウォール介入。重要な判断はツールと送信元 IP を変えて再確認|方向転換:大量のタイムアウト = レート制限の発動。速度を落とし出口を変える。IPS に捕捉されたら空間測量に移り非接触でポートを調べる
- 場面:フィンガープリント識別の信頼度|判定基準:banner は手がかりに過ぎない。複数特徴の投票(cookie/エラーページ/TLS フィンガープリント)が一致して初めて信頼できる。スタックの種別+バージョン範囲まで識別できれば武器を選べる。バージョンは候補の並べ替えに過ぎず、脆弱性は挙動プローブで確認|方向転換:識別できないなら異常な入力でエラーを見る。自前開発でフィンガープリントが無いなら機能点駆動へ
- 場面:JS エンドポイントの掘削|判定基準:chunk マッピング表で抽出の網羅性を判断。優先順位 = admin/internal>UI に入り口のない隠し API>id 付きの権限外アクセス>アップロード/エクスポート>SSRF サービス|方向転換:静的抽出できないなら headless hook でネットワーク層を記録し実行時 URL を録る。強度の高い難読化なら文字列定数のみすくい取る
- 場面:API の未認証/権限外アクセス検証|判定基準:token なし/失効 token/低権限 token の三組を比較。200 かつ本物のデータなら未認証。欠落はしばしばまとまって起きる。権限外アクセスは二アカウント対照で他者のデータを取れて初めて成立|方向転換:全て 401 ならまず低権限 ID を作ってから IDOR へ。id 変更が塞がれたらパラメータの位置/配列ラッピング/旧バージョンを変える
- 場面:漏えいハンティングの順序|判定基準:まず露出即高危をスキャン(.git/.svn/.env/バックアップ/swagger)、次にディレクトリ総当たり。辞書はスタックに合わせて切り替える。①検証可能な認証情報 ②ソースコード ③API リストのいずれかを得たら即利用へ|方向転換:WAF に塞がれたら公開インターネットのパッシブ面へ(コードプラットフォーム/Wayback/検索構文)
- 場面:鍵らしき認証情報を掘り当てた|判定基準:設計上の公開 key とサーバー側秘密鍵を区別し、公式の読み取り専用 whoami API で最小限の生存確認。コード実行/DB/クラウド管理面へ直結できる = 最高価値。ローテーション前に早く検証|方向転換:失効していても捨てない。同じ pattern で履歴 JS/モバイルパッケージ/git 履歴から生きているものを探す
- 場面:OSINT と認証情報への攻撃|判定基準:まずメールアドレスの命名形式を定めて一括生成。漏えい DB の古いパスワードから基語を抽出し、年号や記号の変形を作る。スプレー前にロック閾値を把握し、一巡 1~2 パスワードを広い面で時間差実行|方向転換:人に手がかりがなければ機械の認証情報へ(API key/接続文字列)。MFA で封じられたら事前認証の脆弱性か残存入口へ
- 場面:隠しパラメータの掘削|判定基準:辞書ソース = 自サイト JS>履歴スナップショット>同フレームワークのパラメータ集合>汎用辞書。多次元ベースライン(長さ/ステータスコード/所要時間/エラー)で変化が安定して再現して初めて消費されたとみなす|方向転換:ソースを搾り尽くし、組合せに新たな分岐が無ければ収益はゼロに近い。六次元チェックリスト(名前/位置/エンコーディング/メソッド/型/認証状態)を通過したら移る
- 場面:ブルートフォースが全て 403/302|判定基準:まずランダムパスでベースラインを築く。ランダムパスでも 403 = 一律ブロックの誤検知。403 = 存在するがアクセス禁止、404 より掘る価値がある。WAF の 403(エンコーディング変更/送信元変更)とアプリの 403(パス・ヘッダ・メソッド変更)を区別|方向転換:回避が逓減し無効になったら損切りし、サブドメイン/モバイル API へ
- 場面:偵察をいつ十分とみなすか|判定基準:硬い基準 = 「サービス P に脆弱性 V があり、手法 M で結果 R が期待できる」という反証可能な仮説を書けること。複数ソースの産出が高度に重複 = 発見の収束。低ノイズなら五割でロールバック可能なら打つ、高ノイズなら七八割で動く|方向転換:仮説が成り立たなければまず弱い情報を組み合わせ、攻撃チェーンの欠けを逆算する。次元(人/サプライチェーン/モバイル/クラウド)を尽くさない限り行き止まりではない
