# chains-meta L3 意思決定チェーン骨格(場面→判定基準→方向転換;chains コーパスから蒸留、完全な Q&A は skills/chains-meta/refs/ 参照)
- 場面:同一のインジェクションポイント/脆弱性に固執し、payload バリアントを何十個も変えても進展なし|判定基準:連続 15~25 回の試行で応答が完全に均質(新しいステータスコード/長さ/タイミングの差異なし)=勾配ゼロ、次元をやり尽くし|方向転換:即座に強制的に次元を変える。「もう少しで成功」という感覚で延命しない
- 場面:「あと一歩」か「この道は行き止まり」か区別がつかない|判定基準:信号勾配がある。わずかな差異(エラー変化/遅延変化/挙動の分岐)があれば登坂中。入力がすべて同一出力に写れば平原|方向転換:勾配ゼロなら列挙を止め軸を変える。変えるのは次元(軸)であり同一軸のパラメータではない。方向転換前に保留マーカー(詰まり箇所/試行済み/再検討条件)を残す
- 場面:すべてのリクエストが同じ長さ・同じステータスコードを返す|判定基準:正常なリクエストも絶対にエラーになるべきリクエストも同じページに均される=統一的な遮断層。リクエストがアプリケーション層に到達していない|方向転換:payload ではなく攻撃面を変える。プロトコル入口/パラメータ位置/脆弱性カテゴリを変える
- 場面:応答はまだ通るが明らかに遅くなる|判定基準:良性は速く攻撃特徴は遅い=tarpit。遅延が固定閾値で揃う(すべてちょうど 5s/10s)=人為的遅延|方向転換:時間の判定基準を捨て内容差異/帯外に切り替える。無効ならタイミングに依存しない脆弱性カテゴリ、または tarpit のない入口へ
- 場面:payload が 200 を返すが期待した結果がない|判定基準:陰性+陽性の対照。悪意のある不正リクエストと payload リクエストの body 長/ヘッダ/時間がバイト単位で同一=WAF が 200 を偽装して遮断|方向転換:「WAF 強力な防御」と記録し、アセットマッピングに転じて防御の弱いバイパス経路を探す
- 場面:ツールが「注入不可/脆弱性なし」と報告する|判定基準:エコーの陰性は決して脆弱性の陰性を意味しない。ツールの陰性は「このルールセットが今回は発火しなかった」だけ。手動の最小検証(単一引用符、論理の真偽ペア)で安定した差異を見る|方向転換:ツールの陽性は信頼でき、陰性は門を閉ざさない。他に疑う理由があれば続ける
- 場面:注入が成立するかの判定|判定基準:真偽の分岐こそが注入の判定基準。エラーは構文を変えただけの説明にすぎない。and 1=1/1=2 の応答が安定して二分するとき初めて式が WHERE に入ったと言える|方向転換:まず手動で真偽の分岐を確認してから、ツールでデータを引き出すことを考える
- 場面:本当に行き詰まっているのか低速で進んでいるのか区別がつかない|判定基準:行き詰まり=予算(時間/ラウンド/リクエスト数)内で状態の進展ゼロ(新しい情報なし/新しいアクセスなし/問題空間が縮まらない)。毎ステップ不確実性を減らしていれば低速進行|方向転換:行き詰まったら努力を倍にするのではなく、まず視点を上げて振り返る
- 場面:長時間進展ゼロ、ブロックされているのか方向が間違っているのか区別がつかない|判定基準:全行程で正のフィードバックがゼロ=方向の間違い(無反応ポイント)。正のフィードバックはあったが押し進められない=ブロックされている|方向転換:正のフィードバックゼロなら積み増すのではなく強制的に方向転換。偵察面に戻り正のフィードバックがある新方向を探す。ブロックされているなら対象を絞ってバイパス
- 場面:入口をやり尽くしたか、放棄すべきかの判断|判定基準:カバレッジ行列を作る(入力型/認証セッション/権限外アクセス/ファイル操作/ビジネスロジック)。空白が多い=カバー不足でありやり尽くしではない|方向転換:次元を終えて初めて「やり尽くし」。広さへ転じて面を広げる。放棄時は離脱理由+再検討のトリガー条件を書く
- 場面:各ルートに予算を設ける|判定基準:タイムボックスは対象価値×確度で決める。「あと少し」は反証できない。時間になったら延長は一度だけ、次に何が得られるかを明言できる場合のみ|方向転換:検証可能な次の一手を言えないなら離場必須。保留してローテーション
- 場面:偵察後、多数のポート/対象を前にどれを先に攻めるか|判定基準:悪用成熟度×権限ゲイン×露出面で並べる。まず 1 回のプローブで反証/確認できるアクションで絞り、10 分以内に赤黄緑で分類、赤黄のみに投じる|方向転換:すべて緑なら広さ(サブドメイン/隣接サイト/過去のアセット)へ
- 場面:核心対象が固い vs 周辺の柔らかい標的|判定基準:再利用可能なアセット(認証情報/ドメイン情報/接続性)を産める柔らかい標的を先に取る。レバレッジの三問:ドメイン内か/高権限アカウントはあるか/新しいネットワークセグメントに通じるか|方向転換:攻めあぐねたらアイデンティティ経路(認証情報で正面から)に転じ、次に信頼関係面へ
- 場面:急所を握っている(直接 shell/flag に転換できる)|判定基準:5 つのシグナル。バックエンドにテンプレート管理がある/拡張子を検証しないアップロードポイント/スタッククエリ注入/into outfile/任意ファイル読取で flag まで読める/コマンド実行チャネルがある|方向転換:横展開を止めてまず収束させる。確実に仕留める(バイパス手法を試し尽くす)前に発散する=自殺行為
- 場面:収束中に小さな障害で詰まる(アップロードが一度ブロックされる等)|判定基準:一度の失敗は終点ではなく手がかり。拡張子ブラックリスト/MIME 検証/パス書き込み不可を診断|方向転換:同一プリミティブ内でバイパス手法を変える(拡張子/MIME/ディレクトリ/レンダリング位置を変える)。試し尽くしてから退き次のプリミティブを探す
