# chains-rev L3 意思決定チェーン骨格(場面→判定基準→方向転換;chains コーパスから蒸留,完全な Q&A は skills/chains-rev/refs/ 参照)
- 場面:未知の ELF/PE を手にした最初の 1 分|判定基準:file(アーキテクチャ/strip)→checksec→strings の三連,30 秒で方針を定める|方向転換:strings に可読文字列なし→エントロピーを測定し,エントロピー>7.2 の大きいセクション+UPX0/UPX1 セクション名=パック済み,先にアンパックしてから静的解析へ戻る
- 場面:stripped で main を探す|判定基準:__libc_start_main の第 1 引数(rdi)が main;静的リンク時は _start で最初に引数として渡されるアドレスが main|方向転換:効かない→read/scanf を xref して業務コアを逆算
- 場面:標準パックと独自難読化のトリアージ|判定基準:標準パック(UPX)は入口が小さい stub でセクション名に特徴あり,一瞬でアンパックできる;独自難読化は入口が通常コードだがジャンクコードだらけ|方向転換:upx -d がエラー→UPX! マジックナンバーを修正,または ESP の法則で OEP まで進み,dump+Scylla で IAT を修復
- 場面:VMP/Themida の仮想化パックが脱げない|判定基準:パックは特定の関数だけを保護し,大部分のロジックはネイティブ実行のままで,対外挙動は隠せない|方向転換:アンパックせず,入出力境界(比較、IO、syscall)で hook するか,関数を抜き出して Unicorn をブラックボックス oracle として使う
- 場面:ジャンクコード・制御フロー平坦化が読み取れない|判定基準:不透明述語は入力に依存せず静的評価できる=NOP しても安全;平坦化は先に述語を消し,次に state 遷移値を求めて CFG を復元する|方向転換:量が多い→D810/deflat スクリプト;それでも効かない→動的 trace で実際に実行された基本ブロックだけを取る
- 場面:文字列・定数の実行時暗号化|判定基準:高エントロピーの暗号文ブロックを xref し,それを参照してループ+XOR を持つ小さい関数が復号器|方向転換:単純なら→IDApython で一括復号;使い捨て→復号関数を onLeave で hook;hook が効かない→ロジックを抜き出して Unicorn で単独シミュレート
- 場面:デバッガを起動すると即終了・偽分岐に入る|判定基準:ptrace(PTRACE_TRACEME)、TracerPid、rdtsc の時間差を確認;判定ジャンプを patch するか戻り値を書き換えるのが一番手軽|方向転換:箇所が多く散在→LD_PRELOAD/ScyllaHide で一括無効化
- 場面:ソフトウェアブレークポイント・patch が自己検証に検出される|判定基準:プログラムが .text を 0xCC スキャンするか CRC を計算し,patch をディスクに書き込むと即クラッシュ|方向転換:ハードウェアブレークポイントに変更(バイトを変えない);自己検証関数もまとめて恒真になるよう patch;すべて塞がれたら→qiling/Unicorn でシミュレート
- 場面:動的・静的をいつ切り替えるか|判定基準:アンチデバッグあり/ディスク書き出しが必要→静的から着手;難読化が重い→動的 trace;ロジック理解より入力を求める→angr の find/avoid が 1 桁速い;単一関数を静的解析して 15~20 分進展なしなら強制的に次元を変える|方向転換:トリガーに到達しない→シンボリック実行で条件を逆算
- 場面:標準アルゴリズムか独自実装かの判別|判定基準:フィンガープリント定数を探す:0x9e3779b9=TEA、0x6a09e667=SHA256、AES S-box;魔改造は S-box/ラウンド数/delta だけを変えるので,骨格は不変で diff で差分を見ればよい|方向転換:フィンガープリントなし→ブラックボックスでモデル化
- 場面:独自アルゴリズムのブラックボックス評価|判定基準:差分テスト:1 バイト変更が暗号文の局所だけに影響=バイト単位の写像,テーブルを組めば即破れる;拡散ありで可逆→シンボリック実行で逆算;不可逆 hash がバイト単位で独立→256 回/バイトのブルートフォース|方向転換:強い拡散・広い出力→鍵の由来・実装の誤用を攻める
- 場面:鍵・平文の抽出|判定基準:どんなに強い暗号化でも使用時点では必ず平文になる,暗号化関数の入口と key 引数を監視する|方向転換:使い捨て→鍵生成の瞬間を hook;アンチデバッグに阻まれる→Unicorn で復号関数を抜き出して単独実行;環境に依存→復号後の平文を直接取得
- 場面:crackme の検証ポイント探し|判定基準:main を読まず,"Correct/Wrong" 文字列や strcmp/memcmp を xref して逆算し,比較関数にブレークして期待値を読む;短絡比較→時間サイドチャネル 256^n→256*n|方向転換:通過を求める→判定ジャンプを patch
- 場面:ブレークポイントと watchpoint|判定基準:データ境界(read の戻り箇所、出力関数の直前)に張り,やみくもにシングルステップしない;頻度が高すぎる→条件フィルタを追加;書き換え元を捕まえる→ハードウェア watchpoint|方向転換:すべて空振り→catch syscall でアンカーし,finish で業務層へ浮上
