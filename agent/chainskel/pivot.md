# chains-pivot L3 意思決定チェーン骨格(場面→判定基準→方向転換;chains コーパスから蒸留、完全な Q&A は skills/chains-pivot/refs/ 参照)
- 場面:初期 RCE 後の足場の作り方(foothold ladder)|判定基準:webshell を書いて永続的な主チャネルを築くのを優先。インバウンド HTTP を再利用、外向き通信依存ゼロ、業務トラフィックに混ぜる。リバースシェルは一時チャネルとしてのみ|方向転換:PTY 権限昇格/大ファイル/トンネルデバッグが必要なときだけ一時的にリバースを張る。使い終われば即回収、管理された TTL で常駐させない
- 場面:対象が完全に外向き通信不可(no-reverse)|判定基準:DNS/HTTP/ICMP の外向き通信を層別に検証し、「プロトコル次元」か「宛先次元」の遮断かを判定。全て断たれれば外向き通信なしと確定|方向転換:webshell セッションでの実行に頼るしかない。またはプルモードへ。周期的に制御下の SaaS/ホワイトリストドメインから指示を pull する
- 場面:トンネルを張る前に外向き通信能力を探る|判定基準:curl/nc/dig/ping で層別に TCP 443/80/53、UDP 53/123、ICMP、DNS 再帰をテスト。プローブは擬態し低頻度で|方向転換:全て reset されるならホワイトリスト外向き通信。DNS のフォールバックと強制プロキシ(環境変数/pac)を見て、CONNECT で出る
- 場面:フォワード listen かリバース connect back か|判定基準:デフォルトはリバース。フォワードは公衆網から到達可能なポートが必要でリッスンが目立つ。リバースは NAT/ファイアウォールを自然に通過|方向転換:対象自体が対外サービスを公開しているか、外向きが厳封で内向きに穴があるときだけフォワード。内部層はカスケードしてリバースで境界マシンに接続し中継
- 場面:プロキシ方式の選定(ポートフォワーディング/SOCKS/tun)|判定基準:直接接続できるならプロキシは使わない。ホップが一つ増えるごとに失敗面が倍になる。「対象数×ポート数」のいずれかが集合になって初めて SOCKS に昇格|方向転換:探索モードでは先に SOCKS。収束後に単一ポートフォワーディングへ後退。任意プロトコル/ICMP のときだけ tun(要権限)
- 場面:チャネルの選択(TCP が封鎖された後)|判定基準:TCP は 443>80>53 を優先し、4444/8888 などの高位ポートを避ける。TCP 全封なら DNS>UDP>ICMP。DNS は生存率が最も高いが帯域が極小(KB/s 級)でコマンドチャネル専用|方向転換:ICMP は制御シグナリングのみ。ホワイトリストはドメインフロンティング/正規 SaaS 中継を使用。強制プロキシは CONNECT を通る
- 場面:トンネルが遮断された、または突然リンク断した|判定基準:層別に L3→L4→TLS→アプリケーション層と特定。L4 で遮断ならポートを変更、L7 で遮断なら特徴を変更(uTLS で JA3/SNI を偽装、WebSocket over 443)。特定コマンドが 100% 失敗=特徴マッチ、二分探索でトリガー文字列を特定|方向転換:層ごとに降格。プロトコル変更→キャリア変更→ノード変更。アラートウィンドウで強行しない
- 場面:長い接続が idle-timeout で切られる|判定基準:二分探索で中間デバイスの idle 閾値を測り、アプリケーション層ハートビートは閾値の 1/2~2/3 に設定しランダムなジッターを加える。周期的な規則性が最大の破綻|方向転換:ハートビートで救えなければ短い接続/ポーリングモデルへ。インタラクティブ性を犠牲に安定を得る
- 場面:単層 webshell 上で内部ネットワークの偵察を行う|判定基準:先にパケットを送らずパッシブ六表を得る。ルーティングテーブル、ARP(arp -a)、netstat の既存接続、hosts、DNS キャッシュ、SNMP。非デフォルトの静的ルートは必ず価値あるセグメントに通じる。netstat の対向は既知で接続可能な高成功率の対象|方向転換:パッシブで足りなければ低速で /24 をスキャン、22/80/443/445/3389/1433/3306/6379/8080 のみ
- 場面:深度偵察で新しいネットワークセグメントを発見した後|判定基準:低速 SYN で生存確認後、生きているホストのみフィンガープリント。並列は 10~20 に抑え、/8 に全ポートを噴かない。デュアル NIC マシンは ARP 表でセグメントを跨いだ交差照合で識別|方向転換:スキャンがアラートを発したら即停止、純粋なパッシブスニッフィング(受信のみ送信なし)へ。第二のトンネルリンクを備える
- 場面:どのマシンを踏み台に選ぶか|判定基準:三次元スコアリング。ネットワーク位置(到達可能セグメント数)、監視感度(EDR/ログ)、アクティブ度。理想は「位置が良い + 監視が弱い + 遊休」|方向転換:ドメインコントローラ/要塞ホスト/CI は通過のみで駐留しない(足場を置かない、メモリ socks、使い終われば即解体)。取れなければ次善を選んで維持
- 場面:多層 pivot リンクの管理|判定基準:三層以内に収める。層ごとに遅延が加算され、可用性は乗算される(四層で 99% でも 96% しか残らない)。いずれかが揺れると全リンク断。同じセグメントでは最も安定したマシンを代表に選ぶ|方向転換:同一層で二台によるデュアルアクティブ冗長化。各層で独立したヘルスチェック、再接続のタイミングをずらして雪崩を防ぐ。ある層が検知されたらその層だけを交換し、鎖全体を解体しない
- 場面:低権限ユーザー/足場確保が制限されている|判定基準:リバース接続はリッスン不要で、低権限でも開始できる。/dev/shm はしばしば実行可能で、memfd_create/ld.so で noexec を迂回できる。「書き込み可」と「実行可」は別物。先に mount でマウントオプションを見る|方向転換:足場を置けないなら LOLBin を使う。ssh -D/-R、bash /dev/tcp、netsh portproxy でトンネルを組み立てる
- 場面:DNS のみ外向き通信可の極限場面|判定基準:DNS トンネルをコマンドチャネルとして築く(数十 bps~数 KB/s)。コマンドとファイルはチャネルを分け、ファイルは正規 SaaS に送ってから C2 にダウンロードを通知。検知を下げるには帯域を犠牲にせざるを得ない|方向転換:DNS さえも断たれたらこの道は行き止まりと認め、一回限りのタスクでデータを取って即撤収するか、マシンを変えて偵察に戻り新しい面を探す
