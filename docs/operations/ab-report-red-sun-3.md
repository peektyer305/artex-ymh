## 二、タスク #2 の自律的な貢献の一覧（エビデンスあり）

プラットフォームが**自律的に**完了した部分（人手による投入とは無関係）：

1. Web エントリの完全突破：Joomla の `configuration.php~` バックアップ漏えい → DB 認証情報 → 管理画面 → テンプレートへの WebShell 設置（#1 と同一経路だが、速度は 2 倍以上）。
2. PHP disable_functions 強化への対抗：PwnKit（CVE-2021-4034）によるローカル権限昇格 www-data → root（verifier #12 が独立に再生して確認）。
3. 内部ネットワークの偵察とトポロジ：192.168.93.0/24 の内部セグメント、3 台の Windows ホストのフィンガープリント（DC/WIN2008/WIN7）を発見。
4. **suo5 トンネルの自律的な引き継ぎ**：外部ネットワークに出られない環境で probe 判定 → suo5 アダプタが SOCKS5（127.0.0.1:11113）を確立し、全行程で内部ネットワークのバックボーンとして機能——フェーズ 3.5 の建設目標を実戦で達成。
5. メンバー機の完全制御：impacket atexec による SYSTEM での実行（verifier #13 が確認）、C$ の読み書き、SAM/SYSTEM/SECURITY の 3 つの hive をオフラインで抽出して解析。
6. ドメイン内の列挙：`net group "Domain Admins" /domain` によりドメイン管理者の唯一のメンバーが administrator であることを確認。スプレー対象の陰性マトリクス（付随ツールの規律：手書きではなく impacket を使用）。
7. **fact 訂正のクローズドループ**：パスワードをまず存在しない `TEST\test` に誤って紐付け → 自己反証（fact#375、陰性の結論を正しく inferred と表示） → administrator に修正（fact#382）。#1 で起きた「SUCCESS を FAILURE と誤読して 27 分間空回りした」事故は再発しなかった。
8. flag の 2 経路による独立した再確認：① SMB ファイル読み取り ② atexec による SYSTEM コマンド実行。verifier #14 が再生して確認。

## 五、新ツールチェーンの実戦での挙動

- **suo5**：全体の MVP。外部に出るための踏み台がない状態 → 自動選定 → SOCKS5 で SMB/RPC/ファイル転送を安定して中継し、紅日 3 の「ラストマイル」は到達不能から主経路へと変わった。
- **gogo/naabu/httpx/katana**：偵察の高速化が顕著（gogo のガイダンス修正後は 4 秒/1000 ポート）。
- **impacket**：worker が自律的にインストールして使用（secretsdump/atexec）——「ツール不足」問題は部分的に自己修復した。
- **penelope/mimikatz/fscan/ligolo/lazagne/peass**：今回は出番なし（導入したばかりで、武器庫は次の演習に取っておく）。

## 六、残課題（優先度順）

1. **「認証情報ゼロで DC を直接取得」が依然として自律性の天井である**：2 回ともドメイン管理者認証情報を人手で供給する必要があった。chains ad-* の経路悪用（Kerberoast/AS-REP/ADCS）は本演習環境では客観的に制約されるが、agent によるこうした経路への体系的な試行は深さが足りない——これは chains L3/L4 が本当に使いこなされていないことと直接関係している。
2. **chains の 4 層は依然として実戦上の価値を生んでいない**：L4 には「シナリオトリガー」の仕組み（たとえば検証 agent／停滞検出の発火時に対応するスケルトンを自動注入する）が必要であり、モデルの自覚を待つべきではない。
3. **「頑固さ」の現象（TEST\test への固執）**：反証の仕組みが最終的には訂正したが、訂正までの遅延は依然として大きい——fact の信頼度の補正には、より強固な「まず反証を置く」習慣が必要である（ツール規律と evidenceFirstRule で既に強化済みだが、さらなる観察を要する）。
4. **DC からの flag 直読み vs 完全な掌握**：ゴールは達成したが、ntds.dit/DCSync は未試行（ユーザーが終了を指示）——網羅性は任意項目として残す。

## 七、結論

P0 修正 + トンネル／ツールチェーンの整備により、**プラットフォームは「最後の一撃の直前で崩れる」段階から「完全なエビデンスチェーンを伴ってクリアする」段階へと引き上げられた**。しかし 2 回のクリアはいずれも、ラストマイルで人手による認証情報の供給に依存している——**現時点でのプラットフォームの実像は「ペネトレーション手順の 80% を専門家レベルで遂行できるが、ドメイン管理者認証情報の部分では依然として人手を要する」ものである**。次の重点領域は、chains のシナリオ化された自動注入（L3/L4 を本当に使いこなすこと）+ AD 認証情報経路の体系的な深掘りである。
