# chains-meta · メタ意思決定の問い直し意思決定チェーン(L4 原文インデックス)

> 本類は**主に planner 向け**:作業の割り当てと並び替え、worker が行き詰まっていないかの監視、方向転換/放棄/締めくくりのタイミングの判定を行う。
> worker は、観測の真偽を自ら証明する必要がある場合や行き詰まりの自己点検を行う場合のみ、該当する篇を参照する。

## 使用するタイミング

- worker が長期間成果を出さない場合、本当に行き詰まっているのか進展途上なのかを判断する(meta-stuck-detect)
- 観測結果が疑わしい場合(200 でエコーなし、レスポンスが全て同質)、ツール/環境が騙しているのかを判断する(meta-trust-obs)
- 単一点に執拗に取り組みすぎた場合、「次元を変える」しきい値と方向転換の軸を定める(meta-orthogonal)
- ある入口をやり尽くしたか、放棄すべきかを判断する(meta-give-up)
- 偵察が終わり多数の対象を前に、どれを先に攻めるかを並べる(meta-priority)
- 急所を握っている(getshell プリミティブを既に保持)、発散を防ぐため強制的に締めくくる(meta-close-the-kill)

## 鉄則

- 連続 15~25 回の試行でレスポンスが完全に同質(新しいステータスコード/長さ/タイミングの差異がない)= 情報勾配がゼロ。すぐに次元を変える。「もうすぐ成功する」という感覚で延命しない(refs/meta-orthogonal.md)
- 変えるのは次元(軸)であり、同じ軸上のパラメータ値ではない。方向転換の前に「保留マーカー」を残す(どこで行き詰まったか、何を試したか、いつ戻るか)(refs/meta-orthogonal.md)
- 正常/異常リクエストが同じページに均一化される = 統一遮断層が受け止めており、リクエストはアプリケーション層に全く届いていない(refs/meta-stuck-detect.md)
- エコー陰性は決して脆弱性陰性と等しくない:200 + エコーなしの場合、まず陰性/陽性対照を行い、WAF の偽造レスポンスを除外してから結論を下す(refs/meta-trust-obs.md)
- 急所を握ったらまず締めくくる:shell/flag に直接変換できるプリミティブを握りしめた時、発散 = 自殺。確実に突破したと確認してから発散を許可する(refs/meta-close-the-kill.md)

- `refs/meta-give-up.md` — いつ一つの道を放棄するか、いつ引き返すか(カバレッジマトリクスでやり尽くしたかを判断)

- `refs/meta-priority.md` — 費用対効果による並び替え:どれを先に攻めるか
- `refs/meta-stuck-detect.md` — 行き詰まりの自己点検:遮断された信号の識別

## 使い方

まず本インデックスで篇目と場面節(`### 場面句`)を特定し、次に対応するファイルを Read する。回答/意思決定の際は、その中の判定基準と方向転換ルールを優先して従う。worker は Glob/Grep を使えないため、上記の正確な相対パスで直接 Read する。
